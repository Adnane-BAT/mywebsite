Risk Flow / AEGIS — guide de développement des flows

Quatre nouveaux flows construits uniquement sur les listes SharePoint existantes de la solution « DRG – Gestion des Validations ». Aucune liste ni colonne à créer. Chaque flow est décrit action par action, avec le nom à donner à l'action dans le designer, ses paramètres et ses expressions.

7→4 3 orchestrateurs + 1 child flow. DRG_MiseAJourUtilisateur et DRG_MiseAJourAdministrateur sont supprimés : l'email est lu directement dans la colonne Personne.

1 Principes et prérequis

Règles de construction

  • Tous les flows dans la solution, connexions via références de connexion (SharePoint, Office 365 Outlook) au nom du compte de service.
  • Anti-boucle sans nouvelle colonne : Power Apps écrit avec l'identité de l'utilisateur, les flows écrivent avec le compte de service. Le déclencheur ignore toute modification dont l'auteur (Editor) est le compte de service.
  • Détection du vrai changement : l'action « Obtenir les modifications d'un élément » compare avec la version précédente. Le flow ne traite que si Statut a changé. Le contrôle de version doit être actif sur les listes (il l'est par défaut).
  • Nommer chaque action exactement comme dans ce guide : les expressions y font référence (espaces remplacés par _).
  • Chaque flow est enveloppé dans un Scope Try et un Scope Catch (voir blocs standards).
  • Aucune valeur en dur : site, listes et expéditeur viennent des variables d'environnement déjà créées.

À développer dans l'ordre 04, 01, 02, 03 : le child flow doit exister avant les flows qui l'appellent.

DRG_04_Notification (child flow)

Changement de conception : À la différence du document original, DRG_04 ne lit plus SharePoint (pas de Get_modele ni Get_configuration_email). Les flows appelants construisent directement le message complet (objet, corps HTML, corps secondaire, tokens) et le passent en entrée. Cela réduit les appels SharePoint, la charge, et élimine le risque de modèle manquant à l'exécution.

Dans le Scope Catch de DRG_04, ajouter un appel récursif au child lui-même n'est pas possible (boucle). À la place, envoyer un mail simple via l'action « Envoyer un mail » (Office 365 Outlook) directement aux administrateurs, sans passer par DRG_04 :

Si l'action en échec se trouve dans une boucle ou un Switch imbriqué, result('Try') ne montre que le conteneur : le lien vers le run reste la source fiable.
